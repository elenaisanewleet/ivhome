Надом
DESIGN PACKAGE V4.1 · MINI APP · BOT · DASHBOARD · WEB
Надом — приватный технологический сервис подбора медслужбы с выездом на дом в Москве. Это агрегатор и сервис мэтчинга, не клиника. Надом не оказывает медицинских услуг, не ставит диагнозы и не назначает лечение. Возможность, формат, состав, ETA и итоговую стоимость подтверждает выбранная медслужба.

v4 сохраняет зрелый технологичный каркас v2 (мобильные фреймы, safe-area, статус-трек, ETA/SLA-блоки, чат, price-lock, иконосистему, мелкие mono-лейблы) и возвращает насыщенный цветовой ритм v1 (синий / teal / cream / dust / warn / err, спокойные цветные пилюли и статусы). Документ — единый источник правды для следующего агента-разработчика: ничего из приложения здесь не меняется, только дизайн-система.

Этот файл — спецификация. Реализация выполняется строго по разделам 30 (CodeX), 31 (словарь) и 32 (export). Цвет — не для украшения, а для смысла: статус, приоритет действия, безопасность.
02 — Final brand concept

Брендовая идея

Технологичная приватность с человеческой заботой. Не «капельница ради эффекта», а спокойная инфраструктура: сигнал, узел, подтверждённый маршрут.

Суть

Надом соединяет человека в неудобной ситуации с лицензированной медслужбой. Бренд = «узел связи» + «капля». Не паника, не реклама наркологии — спокойный частный сервис.

Тон

Сдержанный, конкретный, без обещаний. Каждый экран — одно решение. UI понятен за 2–3 секунды стрессующему или уставшему человеку.

Цвет

Графит и молоко как база; accent-синий как навигация; teal как «специалист/действие»; dust/warn/err как мягкие сигналы. Цвет всегда несёт значение.

03 — Product principles

Принципы продукта

UX-правила
01
Один экран — одно решение. Главное действие всегда видно и не перекрыто.
02
Понятность за 2–3 секунды. Заголовок отвечает «что здесь решаю».
03
Спокойствие. Никакого FOMO, сирен, давления. Пользователь может быть в стрессе.
04
Приватность по умолчанию. Телефон и точный адрес — только когда выбранная медслужба подтвердила выезд.
Продуктовые границы
01
Надом — агрегатор, не медорганизация.
02
Не диагностируем, не назначаем, не подбираем состав капельницы.
03
103/112 — спокойная рекомендация, не жёсткий стоп и не сирена.
04
Медицинские детали не уходят в Telegram-уведомления и не логируются.

14 — Animation concepts

Анимации как UX

Анимация = обратная связь, не декор. Длительности 180–320ms для микро, 2.0–2.8s для амбиентных циклов.

Drip

Symbol B. Мягкое падение капли. Welcome, loading, waiting/status.

Pulse

Symbol A. Сигнал/поиск. Matching, status updates.

Ring

Активная точка статус-трека. «Сейчас обрабатывается».

Микроинтеракции
▪
выбор услуги — chip scale 0.98→1 + haptic light
▪
открытие карточки — slide-up 220ms
▪
заявка отправлена — success haptic + ✓
▪
price-lock — fade+scale 0.96→1, ok-haptic
▪
новое сообщение — bubble pop 160ms
▪
смена статуса в dashboard — pill cross-fade
Reduced motion: при prefers-reduced-motion: reduce все циклы выключаются, остаётся мгновенная смена состояния (opacity без движения). Это уже зашито в пример выше и в iv-bag-drop-icon.svg.

17 — Mini App safe-area layout rules

Safe area Telegram Mini App

Ориентир 14/18/19/20. Приложение не должно уходить под верхние контролы Telegram (Close, ⋯, dropdown) и не перекрывать контент нижним CTA. Исправляет проблему из 12_current-miniapp-ui-overlap-reference.png.

‹ Закрыть⋯
НАДОМ
SAFE AREA OK
Контент ниже контролов
Шапка стартует с padding-top ≈ 42px, прогресс и заголовок не под кнопкой «Закрыть».
Зона контента скроллится независимо.
Нижний CTA не перекрывает текст — у него градиент-подложка.
безопасно
Правила
01
Верхний отступ контента ≥ env(safe-area-inset-top, 0) + 28px. Шапка/прогресс/hero — ниже контролов Telegram.
02
Нижний CTA — sticky с градиент-подложкой, контент имеет padding-bottom = высота футера + 12px. Никогда не перекрывать.
03
Чипы переносятся (flex-wrap) или горизонтально скроллятся (chips-scroll) — не наезжают друг на друга.
04
Tap-target ≥ 44×44px. Работает и в Telegram WebView, и в браузер-превью.
05
Использовать BackButton Telegram вместо собственной «‹ Назад» в шапке, когда внутри Telegram.
Анти-паттерн (из reference 12): чипы перекрывают друг друга, нижняя кнопка закрывает текст. В v4 — flex-wrap + sticky footer с подложкой.

Дублировать токены в apps/mini-app/src/App.css через :root и [data-tg-scheme="dark"] / @media (prefers-color-scheme: dark).

Telegram viewport / safe area / theme
▪
Не ломать themeParams: читать Telegram.WebApp.themeParams и мапить на токены; собственная палитра — fallback.
▪
Safe area: контент-обёртка padding-top: max(env(safe-area-inset-top), 28px); футер padding-bottom: max(env(safe-area-inset-bottom), 16px).
▪
?theme=dark / ?theme=light: читать query → выставлять data-tg-scheme на <html>, перекрывая авто-определение (для браузер-превью).
▪
Использовать BackButton/MainButton Telegram внутри WebApp; HTML-футер — fallback вне Telegram (уже реализовано в useTelegramButtons).
Layout / overlap
▪
Чипы: .chips{flex-wrap:wrap} ИЛИ .chips-scroll{overflow-x:auto}. Никогда не absolute-позиционировать чипы.
▪
Нижний CTA — sticky/fixed внутри фрейма с градиент-подложкой; у скролл-контейнера padding-bottom = высота футера + 12px.
▪
Один скролл-контейнер на экран (.s-body{overflow-y:auto}), шапка и футер — flex-shrink:0.
Каталог услуг + payload

Каждая медслужба = список услуг с диапазоном цены. Расширить тип оффера полем services[]. Payload заявки:

Делать

  • custom-request → создаёт заявку → сразу открывает чат с контекст-плашкой
