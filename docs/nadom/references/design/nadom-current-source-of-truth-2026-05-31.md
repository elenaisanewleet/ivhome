## 1. Главная продуктовая формула

Публичный бренд: `Надом / Nadom`.

Внутреннее техническое название / repo codename: `IVhome`.

Надом — приватный технологичный сервис подбора медслужбы с выездом на дом.

Надом помогает быстро понять:

- какая медслужба может приехать;
- сколько ждать ответа;
- сколько ждать прибытия после подтверждения;
- какая ориентировочная стоимость;
- какие условия подтверждает выбранная медслужба.

Надом — агрегатор / marketplace / matching-сервис, не клиника.

Надом не оказывает медицинские услуги, не ставит диагноз, не назначает лечение, не рекомендует препараты, состав капельницы или схему терапии.

Медицинскую возможность, формат помощи, состав услуги, выезд и финальную стоимость подтверждает выбранная медслужба / клиника / медицинская организация.

Короткая формула для UI:

> Надом помогает подобрать медслужбу с выездом на дом — приватно, быстро и без лишних звонков.

Ещё короче:

> Подберём медслужбу с выездом на дом по времени, стоимости и условиям.

## 2. Что изменилось после свежих файлов

Свежие файлы не отменяют основу `nadom-final...md`, но усиливают и уточняют её.

### Принято как новое главное

1. Визуал уходит от просто “мягкого pastel health-tech” в более строгий, технологичный, символический, приватный и почти логотипный стиль.
2. Главная визуальная идея: 2–3 узла / точки + короткие связи. Это символ подбора, маршрутизации, связи пользователя с медслужбой и выезда на дом.
3. Нельзя копировать референс кремчекбота. Нужно своё решение Надом.
4. Лучший базовый знак: абстрактная буква `Н` из 3 узлов и 2 связей. Альтернативы: дом-узел, локация-связь, абстрактный маршрут.
5. В flow добавляется обязательная функция продукта: связь со специалистом выбранной медслужбы после карточки, но до финального подтверждения заявки.
6. Связь со специалистом — обязательная функция системы, но не обязательный шаг для каждого пользователя. Пользователь может пропустить чат и подтвердить заявку, если всё понятно.
7. Emergency / 103–112 остаётся рекомендательным safety layer, не блокирующим hard-stop.
8. Bot flow должен быть коротким: вход, Mini App, статусы, поддержка. Основной сценарий живёт в Mini App.

### Что считаем устаревшим или не переносим

- `партнёр` как user-facing термин;
- `Домой`, `IVhome` в пользовательском UI;
- `клиника Надом`, `врач Надом`, `наш врач`;
- жёсткий emergency hard-stop без возможности продолжить подбор;
- врачей, стетоскопы, красные кресты, сирены, больничную графику;
- капельницу как главный бренд-символ или основную универсальную CTA;
- длинные welcome-инфографики;
- стерильный юридический тон на каждом экране;
- “медицинская организация” в каждой строке UI;
- все большие таблицы из старых файлов как обязательные правила — использовать их только как справочник.

## 3. Аудитория и MVP-фокус

Фокус MVP: Москва.

Основные сценарии:

- плохо после алкоголя / праздника;
- похмелье;
- запойная или около-запойная ситуация;
- интоксикация / отравление веществами;
- срочный неэкстренный выезд;
- плановый выезд специалиста на дом;
- близкий человек помогает найти вариант.

Главная боль пользователя: не хочется гуглить десятки сайтов, звонить в разные места, объяснять деликатную ситуацию, получать мутные цены и не понимать, кто приедет и когда.

Сервис должен ощущаться не как клиника, не как наркологический лендинг, не как бот-доктор и не как подпольный сервис, а как приватная технологичная маршрутизация запроса.

## 4. Терминология

Основной user-facing термин: `медслужба`.

Словарь замен:

- партнёр → медслужба;
- список партнёров → список медслужб;
- карточка партнёра → карточка медслужбы;
- партнёр подтвердил → медслужба подтвердила;
- подобрать партнёра → подобрать медслужбу;
- специалист партнёра → специалист медслужбы;
- стоимость подтверждает медслужба.

Можно использовать:

- медслужба;
- выездная медслужба;
- выбранная медслужба;
- специалист медслужбы;
- специалист выбранной медслужбы;
- выездная бригада;
- клиника;
- выбранная клиника;
- медицинская организация;
- медицинский выезд на дом;
- выезд на дом;
- вариант;
- предложение;
- карточка медслужбы;
- условия выезда.

`Клиника` можно использовать, если речь о фактической клинике / медицинской организации.

`Медицинская организация` использовать точечно: consent, лицензии, юридические места, передача данных, ответственность.

Не использовать:

- клиника Надом;
- врач Надом;
- наш врач;
- лечим;
- назначим;
- диагностируем;
- подберём капельницу;
- гарантируем результат;
- безопасно всем;
- полная анонимность.

## 5. Privacy / anonymity

В коротких публичных текстах можно:

- анонимный подбор;
- анонимный поиск;
- приватно;
- конфиденциально;
- без лишних звонков;
- без публичного поиска;
- без долгих объяснений по телефону.

В consent и юридически чувствительных местах писать точнее:

> Для подтверждения выезда выбранная медслужба может запросить данные, необходимые для оказания услуги.

Ключевые правила:

- собирать минимум данных;
- район / округ — раньше точного адреса;
- телефон и точный адрес не собирать заранее, если можно уточнить их после выбора медслужбы;
- не хранить лишние медицинские детали;
- не писать медицинские подробности в Telegram;
- не дублировать содержание чата со специалистом в Telegram push;
- чувствительные поля помечать Encrypted или Hash;
- не логировать токены, адреса, телефоны, персональные и медицинские данные;
- Telegram initData обязательно валидировать;
- доступ к admin / dashboard только по ролям;
- audit logs для важных действий;
- не коммитить `.env`, Telegram bot token и любые secrets.

## 6. Emergency / 103–112

Emergency-блок — рекомендательный safety layer, не блокирующий hard-stop.

Логика:

- Надом спокойно рекомендует 103 / 112 при острых симптомах;
- пользователь может продолжить подбор медслужбы;
- сервис не ставит диагноз;
- сервис не оценивает тяжесть состояния;
- решение о медицинской возможности и формате помощи принимает выбранная медслужба.

Канонический текст:

> Если состояние кажется острым или быстро ухудшается — лучше сразу обратиться за экстренной помощью: 103 или 112.
>
> Надом может показать варианты выезда, но детали и возможность помощи подтверждает выбранная медслужба.

Кнопки:

- Позвонить 103;
- Позвонить 112;
- Продолжить подбор.

Визуально: спокойно, мелко, без сирен, красных крестов, паники и агрессивных warning-плашек. Красный / бордовый — только маленький функциональный акцент для 103/112.

## 8. Связь со специалистом медслужбы

Это новое обязательное требование продукта.

Где появляется:

- на карточке выбранной медслужбы;
- перед подтверждением заявки;
- в статусе ожидания;
- в подтверждённых деталях выезда.

Кнопки:

- Написать специалисту;
- Открыть чат;
- Пропустить и подтвердить;
- Вернуться к заявке.

Зачем:

- уточнить личные вопросы;
- обсудить состояние;
- уточнить формат помощи;
- согласовать удобное время;
- дать медслужбе понять, достаточно ли информации;
- снизить тревогу пользователя без лишних звонков.

Важно:

- чат со специалистом — функция обязательная, но шаг необязательный;
- пользователь может пропустить чат;
- медслужба может подтвердить заявку без чата, если всё понятно;
- Telegram-уведомления по чату должны быть нейтральными;
- содержание чата не логировать в обычные app logs;
- доступ к чату только у пользователя, выбранной медслужбы и роли поддержки при необходимости.

## 9. Карточка медслужбы

Карточка должна помогать выбрать быстро, без перегруза.

Обязательные элементы:

- название медслужбы / клиники;
- лицензия / статус проверки;
- район / зона выезда;
- время ответа / подтверждения;
- ожидаемое время прибытия после подтверждения;
- ориентировочная стоимость;
- условия;
- рейтинг;
- кнопка связи со специалистом;
- кнопка подтверждения заявки;
- пометка, что детали подтверждает медслужба.

SLA всегда разделять:

1. время ответа / подтверждения медслужбы;
2. ожидаемое время прибытия после подтверждения.

Пример:

> Медслужба отвечает обычно за 5–10 минут  
> Ожидаемое прибытие после подтверждения: от 40 минут  
> Стоимость: ориентировочно от 8 500 ₽  
> Детали и возможность выезда подтверждает медслужба

## 10. Tone of voice

Русский язык.

Тон: коротко, спокойно, человечески, Telegram-native, взрослый, уверенный, слегка премиальный.

Надом звучит как приватный технологичный помощник, не врач, не клиника, не продавец, не наркологический лендинг, не бот-доктор и не юридический документ.

Можно:

- короткие фразы;
- пустые строки;
- мягкие маркеры;
- понятные кнопки;
- спокойный разговорный язык.

Нельзя:

- стыд;
- давление;
- драма;
- медицинский пафос;
- обещания лечения;
- “лучшие врачи”;
- “срочно, осталось мало мест”;
- канцелярит на обычных UI-экранах.

## 11. Визуальная система

Главный вектор: суперминимализм + технологичность + строгость + анонимность + приватность + ощущение дорогого сервиса + человеческая ясность.

Ключевая метафора: не медицинская процедура, а приватная маршрутизация.

Основной визуальный язык:

- 2–3 узла / точки;
- короткие связи;
- чистый знак;
- много воздуха;
- сильный символ вместо иллюстрации;
- light/dark compatibility.

Палитра:

- `#7EB8D4` — базовый акцент, но не обязан доминировать;
- молочный / почти белый;
- графит / почти чёрный;
- мягкий серый;
- приглушённый синий;
- пыльный бордово-розовый как редкий акцент;
- приглушённый красный только для 103/112.

Shape language:

- карточки: radius 20–24;
- кнопки: radius 16–18;
- badges: pill radius 999;
- иконки: 2–3 узла, stroke около 2px;
- линии: короткие, без сложной сетки;
- тени: мягкие, почти незаметные.

Запрещено визуально:

- generic AI/SaaS gradients как основной приём;
- ярко-зелёные галки;
- красные кресты;
- сирены;
- фото врачей;
- стетоскопы как главный образ;
- жёлтые смайлы;
- агрессивные warning-плашки;
- слишком уютный домик;
- слишком нежный wellness-стиль;
- больничный шум.

Главный знак:

- базовый вариант: абстрактная `Н` из 3 узлов и 2 связей;
- смысл: Надом как приватная маршрутизация запроса;
- должен работать в Telegram-аватарке, splash, favicon, welcome, empty/loading states;
- не должен дублировать молекулу из референса.

## 13. Welcome / BotFather

Не делать длинную инфографику.

Задача welcome-визуала — первое ощущение бренда, не полное объяснение продукта.

Формат:

- крупное `Надом`;
- один короткий оффер;
- 2–3 маркера;
- маленькая строка 103/112;
- один минималистичный символ: узлы / связи / абстрактная Н / маршрут.

Пример текста:

> Надом  
> Подберём медслужбу с выездом на дом  
> Приватно · По времени · По условиям  
> При острых симптомах — 103 или 112

## 15. Admin / medservice MVP

MVP работает с ручным подтверждением.

Admin / medservice должны видеть:

- новую заявку;
- район / зону;
- профиль запроса;
- желаемое время;
- выбранную медслужбу;
- чат / необходимость уточнения;
- текущий статус;
- возможность подтвердить / отклонить;
- возможность зафиксировать стоимость;
- ETA;
- заметки без лишних чувствительных деталей.

Важно:

- не раскрывать заявку всем медслужбам;
- передавать данные только выбранной медслужбе;
- screening status хранить без диагностических выводов;
- audit log для смены статусов, цены, подтверждений, доступа к чату;
- роли: admin, support, medservice operator, medservice specialist.

## 18. Короткая инструкция для вставки в Custom Instructions / Project Instructions

Работай по `Надом / Nadom — единый актуальный source of truth`. Публичный бренд — Надом / Nadom, IVhome только внутренний repo codename. Надом — приватный технологичный сервис подбора медслужбы с выездом на дом, не клиника. Не использовать “Домой”, “партнёр” в UI, “клиника Надом”, “врач Надом”, “наш врач”. Главный user-facing термин — медслужба; “медицинская организация” использовать точечно в consent/legal/license.

Надом не оказывает медуслуги, не ставит диагноз, не назначает лечение, не рекомендует препараты, состав капельницы или схему терапии. Детали, формат помощи, возможность выезда и финальную стоимость подтверждает выбранная медслужба / клиника / медицинская организация.

Emergency / 103–112 — рекомендательный safety layer, не блокирующий hard-stop: спокойно рекомендовать 103/112 при острых симптомах, но пользователь может продолжить подбор. Сервис не оценивает тяжесть состояния.

MVP-flow: /start → welcome → consent → emergency recommendation → профиль помощи → район/геозона → время/срочность → список медслужб → карточка медслужбы → связь со специалистом выбранной медслужбы → подтверждение заявки → ручное подтверждение admin/медслужбой → статус → price lock → ожидание/выезд → завершение → рейтинг.

Связь со специалистом медслужбы — обязательная функция продукта, но необязательный шаг пользователя. Пользователь может написать специалисту после карточки или пропустить чат и подтвердить заявку.

Визуал: суперминимализм + технологичность + строгость + анонимность + приватность + ощущение дорогого сервиса. Главный язык — 2–3 узла/точки и короткие связи, символ маршрутизации и подбора. Лучший базовый знак — абстрактная Н из 3 узлов и 2 связей. #7EB8D4 — базовый акцент, но не обязан доминировать. Можно молочный, почти белый, графит, мягкий серый, приглушённый синий, пыльный бордово-розовый. Без generic AI/SaaS gradients, красных крестов, сирен, врачей, стетоскопов, жёлтых смайлов, ярко-зелёных галок, wellness-сахарности и больничного шума.

Privacy/security: минимум данных; точный адрес и телефон не собирать заранее; не хранить лишние меддетали; не писать медицинские подробности в Telegram; не логировать токены, адреса, телефоны, персональные и медицинские данные; sensitive поля Encrypted/Hash; Telegram initData валидировать; доступ по ролям; audit logs; не коммитить `.env` и secrets.

Codex: только маленькие draft PR, не мержить автоматически. Всегда указывать branch name, PR scope, files to change/not touch, validations, privacy/security constraints, naming rules и visual requirements.
