# @nadom_bot — Стратегия и архитектура

## Позиционирование

@nadom_bot — единая точка входа в Mini App Надом для поиска лицензированных медслужб, работающих на выезд.

Бот не оказывает медицинские услуги, не диагностирует, не назначает лечение, не рекомендует состав или режим терапии. Бот запускает Mini App, где пользователь сравнивает медслужбы и отправляет запрос. Детали, медицинскую возможность и финальную стоимость подтверждает выбранная медицинская организация.

## Роль в продукте

| Действие | Канал |
|---|---|
| Первый контакт, старт | Бот → /start → кнопка → Mini App |
| Подбор варианта | Mini App |
| Чат с медслужбой | Mini App |
| Подтверждение заявки | Mini App |
| Уведомления о статусе | Бот → кнопка → Mini App |
| Поддержка | Бот → отдельный канал поддержки |

Бот **не заменяет** Mini App. Он запускает его и отправляет уведомления о статусе заявки.

## Принципы тона

- Русский язык, прописные буквы в начале предложений, без избыточных заглавных.
- Спокойно, коротко, без медицинской драмы.
- Никаких обещаний результата лечения.
- Никаких медицинских деталей в уведомлениях бота.
- Мягкие символы: 🫧 для приветствия/онбординга. Без эмодзи в критических / экстренных сообщениях.
- Стиль Telegram-native: короткие абзацы, пустая строка между ними.

## Архитектура команд

### Команды MVP

| Команда | Назначение |
|---|---|
| `/start` | Запуск. Приветствие + кнопка Mini App |
| `/help` | Краткая справка + кнопка Mini App |

Все остальное — в Mini App. Для MVP достаточно двух команд.

### Inline-кнопки

Все inline-кнопки типа `web_app` — открывают Mini App напрямую из чата.

| Кнопка | Когда |
|---|---|
| `подобрать вариант` | В ответе на /start |
| `открыть Надом` | В ответе на /help и в уведомлениях |

### Menu Button

BotFather → `/setmenubutton` → `Web App` → настроить на URL Mini App.
Это добавляет постоянную кнопку-гамбургер для открытия Mini App прямо из чата.

## Стратегия уведомлений

Бот отправляет только уведомления об изменении статуса заявки. В тексте уведомления:

- **Нет** медицинских деталей, адресов, имён специалистов, диагнозов.
- Только: статус обновлён → кнопка → Mini App.
- Пользователь видит детали только внутри Mini App, где соблюдается приватность данных.

Образцы уведомлений по статусам:

| Статус | Текст уведомления |
|---|---|
| `clinic_review` | Статус заявки обновлён. Откройте Надом, чтобы посмотреть детали. |
| `quote_provided` | Стоимость уточнена. Откройте Надом, чтобы подтвердить. |
| `booked` | Заявка подтверждена. Откройте Надом, чтобы посмотреть детали. |
| `en_route` | Специалист выбранной медслужбы выезжает. Откройте Надом. |
| `completed` | Визит завершён. Откройте Надом, чтобы оставить оценку. |

## Приватность

- Бот не собирает и не хранит медицинские данные.
- Бот не запрашивает адрес, телефон или медицинские сведения в чате.
- Все чувствительные данные передаются только через Mini App с валидацией initData.
- Бот работает в privacy mode — получает только сообщения, начинающиеся с `/`.
- Если пользователь случайно отправляет медицинские данные в чат — бот вежливо перенаправляет в Mini App.

## Экстренный слой

При любых симптомах, требующих экстренной помощи, бот указывает 103 или 112 как спокойную рекомендацию — не как панический баннер. Надом не является экстренной службой.

## BotFather — Privacy Mode

Включить: BotFather → `/setprivacy` → `Enabled`

Бот получает только сообщения с `/`. Не читает все сообщения чата. Это важно для MVP.

## Вертикальная лента (Bot Channel / Notification)

Для MVP: уведомления отправляет бот напрямую в личный чат пользователя через `sendMessage`.
Канал или группа — вне скоупа MVP.

## Масштаб после MVP

Не часть MVP. Не проектировать сейчас:
- Inline-режим
- Групповые чаты
- Web App Payment
- AI-диалог внутри бота
- Многоступенчатый онбординг через чат

Весь сервисный диалог — в Mini App.
